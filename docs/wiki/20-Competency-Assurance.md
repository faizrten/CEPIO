# Competency & Assurance

## Why competency matters

The CEPIO North Star is **thin infrastructure, thick Industry IQ**. Product maturity therefore cannot be measured by ontology size, connector count, cache size or runtime feature count alone.

The central question is:

> **How much real industrial work can CEPIO support through a stable, reusable, evidence-backed and governed operating contract?**

Competency & Assurance is therefore a first-class product discipline and one of the primary measures of Industry IQ quality.

## From structural validity to operational capability

```text
Ontology / schema validation
"Is the model structurally valid?"
              |
              v
Semantic competency
"Can CEPIO represent the required industrial capability?"
              |
              v
Runtime competency
"Can CEPIO retrieve evidence and execute permitted capability?"
              |
              v
Skill / procedural competency
"Can a bounded procedure perform the industrial task?"
              |
              v
Agent competency
"Can an AI system reason correctly from authorized CEPIO evidence?"
              |
              v
Operational competency
"Can the governed loop produce and verify a real outcome?"
```

A domain is not mature simply because its ontology classes validate.

## Persona-driven competency model

Competency connects directly to target users and industrial decisions:

```text
Domain
  x
Persona
  x
Responsibility
  x
Decision
  x
Competency Question
  x
Required CEPIO Capability
```

Acceptance chain:

```text
Persona
  -> Job / responsibility
  -> Decision
  -> Competency question
  -> Evidence requirements
  -> Required semantics / Skill / Function / Decision / Action
  -> Assurance result
```

This is the bridge between Target Users and reusable Industry IQ.

## Example

A Reliability Engineer competency should not ask only whether `FailureMode` exists.

A stronger question is:

> Given increasing compressor vibration, previous failure history, current production exposure and outstanding maintenance work, should intervention occur now, and what evidence supports the recommendation?

That single competency pressures:

- equipment identity;
- `ConditionObservation`;
- temporal state;
- failure history;
- relationship traversal;
- production exposure;
- maintenance/work context;
- provenance;
- uncertainty;
- Function execution;
- Skill execution;
- Decision capability;
- policy and authority;
- recommendation/action separation;
- verified Outcome where action occurs.

That is a measure of industrial intelligence, not vocabulary count.

## Capability alternatives

The drilling v0.3 pack uses a `capability-alternatives` contract. CEPIO may satisfy a capability through an approved canonical semantic composition rather than copying the literal vocabulary of IADC, WITSML, OSDU, PPDM or another benchmark.

This is important to the current product thesis:

> **Thick Industry IQ does not mean thick duplicated standards vocabulary.**

External standards challenge and inform CEPIO. They do not automatically become canonical CEPIO semantics.

## Current operational assurance evidence

The drilling operational-assurance fixture exercises representative deterministic gates including:

1. **Temporal** — distinguish valid-time state from what CEPIO knew at different transaction times.
2. **Provenance** — trace a property through source record, observation time, mapping version and transformation run.
3. **Authority** — resolve scoped current authority.
4. **Policy + kinetic** — reject execution by an AI recommender, allow an authorized human and preserve Decision-to-Action linkage.
5. **Operator evidence** — reject citations absent from the current evidence bundle.

The fixture proves representative governed runtime behavior. It does not establish live industrial operation or production readiness for an entire domain.

## Skill / procedural assurance

The current Skill model adds a stronger procedural contract than semantic questions alone:

```text
Skill package
 -> declared dependencies
 -> runtime binding
 -> actor-aware preflight
 -> READY / BLOCKED
 -> bounded execution host
 -> evidence acquisition
 -> Functions
 -> optional Decision proposal
 -> result / assurance evidence
```

Important boundaries:

- dependency declaration does not create capability;
- READY preflight is actor/runtime aware;
- a Skill does not gain raw runtime/source access;
- Decision capability does not automatically grant Action authority;
- recommendation-only capability can deliberately block actors whose direct execution authority would exceed the Skill contract.

## Agent assurance

CEPIO agents/operators are constrained by authenticated evidence and capability surfaces.

Current patterns include:

- governed REST/MCP access;
- evidence records with deterministic/current-run identity;
- fail-closed unknown citation handling;
- actor-scoped reads and Functions;
- Skill evaluation through the Application Contract;
- least-privilege Foundry qualification profiles.

For Microsoft-hosted agent workloads:

> **Microsoft owns generic agent execution. CEPIO owns industrial agency.**

A live Foundry-hosted G1 qualification path exists for the Reliability lighthouse, but repository implementation does not by itself establish a successful live environment PASS.

Agent assurance must distinguish:

- tool/protocol correctness;
- evidence correctness;
- reasoning/answer correctness;
- Decision correctness;
- authority correctness;
- operational outcome correctness.

One should not be inferred from another.

## Operational assurance

Operational competency is the strongest layer:

```text
Observe
 -> Understand
 -> Reason
 -> Decide
 -> Authorize
 -> Act
 -> Verify
 -> Outcome
```

Mainline workflow/action foundations now support durable execution, external verification/reconciliation and Outcomes, but the current v0.5 CONNECT release gate still requires a real multi-source industrial proof with live writeback/read-back/reconciliation.

## Performance competency

Performance Contracts add another important acceptance dimension: can CEPIO connect industrial evidence to objectives, KRs, KPIs, guardrails, accountability and governed response pathways without universalizing one organization's formula or operating model?

Industry Performance Reference Packs should therefore be evaluated for:

- organization-neutral KPI identity;
- reusable driver/contribution semantics;
- guardrail meaning;
- reference persona accountability;
- specialization correctness;
- suppression/rebinding behavior;
- absence of customer-specific targets/formulas in the reference layer.

## Generalization and competency

Generalization and assurance share evidence but answer different questions:

- **Generalization:** does the capability remain reusable across operating models, customers and platform bindings?
- **Assurance:** is the answer, recommendation or action justified by available evidence and authority?

Gap decisions remain:

`CORE / DOMAIN / MAPPING / PROFILE / REJECT`

Desired long-term pattern:

```text
More domains and personas
        +
Higher competency coverage
        +
More capability / Skill / pack reuse
        +
Fewer Core changes
        +
Fewer customer-specific exceptions
        =
Stronger reusable Industry IQ
```

## Platform-portability assurance

Because CEPIO aims to be portable Industrial Operating Intelligence, an important proof is:

> Can the same competency question, Skill and Decision contract behave consistently when enterprise context is supplied by different platform bindings?

```text
Fabric context ----+
                   |
Cognite context ---+--> same CEPIO competency / Skill / Decision
                   |
OSDU context ------+
```

The underlying evidence location may differ. The industrial operating contract should remain stable.

Provider-neutral Binding Contract and Fabric parity work are early evidence toward this direction; real cross-provider production qualification remains separate.

## Assurance maturity model

| Layer | Acceptance question | Current evidence boundary |
|---|---|---|
| **Semantic** | Can approved concepts/compositions represent the capability? | deterministic harnesses and frozen packs |
| **Runtime** | Can the actor retrieve/trace evidence and invoke permitted capability? | representative runtime/operational fixtures |
| **Procedural / Skill** | Can a bounded Skill perform its declared procedure? | Skill binding/preflight/execution contracts and focused reference Skills |
| **Agent** | Can an AI system reason correctly using authorized CEPIO evidence? | governed Operator/MCP/Foundry qualification paths; comprehensive answer-quality proof remains further work |
| **Operational** | Can the full loop produce a verified industrial outcome? | workflow/action verification foundation; live multi-source product qualification still open |

Uncovered dimensions should remain `NOT_RUN` or explicitly uncovered rather than being inferred as passes.

## Competency as an Industry IQ contract

A mature reusable Industry IQ capability/pack should increasingly declare:

- target domains;
- target personas;
- decisions supported;
- frozen competency questions;
- evidence requirements;
- semantic dependencies/compositions;
- Skills and Functions;
- Decision patterns;
- permitted Actions;
- policy/authority assumptions;
- performance semantics where relevant;
- runtime assurance gates;
- evaluation fixtures;
- known gaps/exclusions.

This makes Industry IQ testable rather than merely descriptive.

## Product quality metric

Conceptually:

```text
CEPIO maturity
=
Competency Coverage
x Runtime Capability
x Generalization
x Evidence Quality
x Governed Actionability
x Operational Reliability
```

This is not a literal numeric score. The actual governed v1 completion percentage comes from `config/v1-scorecard.yaml`.

## Current v1 scorecard relationship

The canonical v1 score currently remains **69/100** at its pinned evidence snapshot. New merged assurance/capability work does not automatically change that number; score changes require governed evidence updates.

Roadmap release gates, competency results and the v1 numeric score are related but distinct claims.
